# Web 迁移记录

检查起点是已有完整 TypeScript 工程和 `build/web-mobile`、`build/web-desktop`。没有从压缩 JS 反推源码。旧 Web 包缺少可信的源码清单，不能据修改时间证明它与当前源码完全对应；它保留为运行基线。新的交付包通过内容哈希关联源码和 Web 构建。

`profiles/v2/packages/builder.json` 的个人历史记录包含 Android、小游戏和 openpaas 发布任务。业务脚本扫描未发现 wx/tt/jsb 等平台 API 调用；历史构建记录不等于当前业务依赖。`settings` 的多平台 Bundle 压缩默认项属于 Creator 配置，保留它们不代表引入 SDK。工具不会按关键词自动删除代码。

当前网页使用 Creator 输入、音频和资源接口，`sys.localStorage` 承载唯一新版存档。奖励、复活、领取等均在已有本地事务流程中完成，没有重新接入广告或支付。`build-templates/web-mobile`、`web-desktop` 提供网页外壳和竖屏布局，`preview-template` 提供编辑器预览外壳，必须保留源码模板。

本次修复资源加载错误传递，以及审查发现的拖拽与消除竞争、消除动画期间超时误判、加载失败无重试问题。未改预期玩法、美术、奖励数值、关卡、存档键、序列化属性和 UUID。Excel 导出消除 Windows 机器路径；构建改为受版本控制的显式 Web 配置。私钥、个人 profiles、Git 历史、依赖安装目录和生成缓存不进入源码包。

限制：引擎仍需要 Creator 3.8.3；首次导入会重建资源缓存。浏览器存档受 origin、隐私模式和存储权限影响，不跨设备同步。声音受浏览器用户手势策略约束。随机局面和时间相关奖励不是确定性回放；“可重复构建”指相同源码和配置能重建可运行产物，不承诺引擎生成文件逐字节相同。Creator 报告原有循环模块依赖，完整 TypeScript 检查也有原有引擎声明问题，详见验证记录。

全新目录验证还发现：直接把符号链接别名 `/tmp/...` 传给 Creator 时，其编译器把脚本解析为 `/private/tmp/...`，导致组件 UUID 注册查找不一致。仅重复构建不能修复。工具改为真实路径后，同一份源码在无原工程缓存的目录成功构建，入口与所有组件脚本均恢复。该检查是必需的，不能仅以退出码 36 判定成功。
